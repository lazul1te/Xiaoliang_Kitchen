# 拿手菜小本本

> 好好做饭，也好好记录。

一家人一起记的菜谱微信小程序。用法：
- 像翻餐厅菜单一样挑今天要做的菜，菜篮自动合出买菜清单。
- 做的时候一步一步看，带计时。
- 做完打个卡，日历上记着哪天做了什么。

每个人有一本只有自己能看的「我的小本本」，还可以建家庭本本、用家庭码申请加入，家庭本本里的人都能看、都能改。它是原生小程序（JavaScript）加微信云开发，不用自己的服务器。用免费环境和体验版就能一直用，不花钱。

## 功能

- **小本本**：
  - 每人自动有一本只有自己能看的「我的小本本」；家庭本本里的人一起看、一起改。菜单左上角一直显示正在用的那本，点一下就能切换，也能设打开小程序时先进哪本。
  - 建一本家庭本本，把家庭码告诉家人，或者发一张邀请卡片给 TA。TA 申请以后，本主（建这本的人）同意了才算加入；退出不用谁同意。
  - 新建时可以把「我的小本本」里的菜复制过去；平时在菜谱详情页也能把一道菜复制到另一本。
- **菜单**：左边分类，右边菜品卡片。能按菜名、原料、标签搜；搜不到的一键记进想吃清单。
- **菜谱**：
  - 原料分主料、辅料、调料，带用量。
  - 做法一步一项，每步能配照片、带计时。
  - 还有小贴士、难度、用时、熟练度。
- **先下单再开始做**：在菜谱里点「开始做」，会先去菜篮下单，下好单直接开始做这道。
- **做菜**：一步一屏大字显示；计时到点会震动、响提示音；做菜时屏幕不灭。
- **一起做**：买完菜，点菜单上的几道菜一起做。
  - 先备菜：要腌、要泡的步骤提前提醒，用时长的先做，原料用量按份数算好。
  - 上面按菜切换，每道菜停在各自那一步；计时器各走各的，到点写明是哪道菜第几步。
  - 中途退出了，回来接着做；都做好了就开饭。
- **菜篮和买菜清单**：
  - 这本里大家点的菜都放进菜篮，原料按份数自动合并。
  - 清单会对比家里的库存，家里有的不提醒。
  - 买到一样勾一样，大家同步；也能一键复制发到微信。
- **点菜单**：
  - 像饭店点餐一样下单：选哪天、哪一顿，写口味备注、谁点的、谁掌勺，生成带编号的点菜单。
  - 下单以后还能加菜，或者点「改一改」改哪顿、口味、谁掌勺（撤单也在这里）。
  - 编号只算开过饭的：撤单不占号，下一单还是这个号。
  - 「点菜单记录」里有正在进行的那单和开过饭的每一单，能再来一单、分享这顿饭。
  - 能发成小程序卡片给家人，也能存成一张小票样子的图片。
- **开饭啦**：做好了点「开饭」，拍一张整桌的照片、给每道菜打个分，一次把这顿的菜都记进做菜记录；没做的菜留在菜篮里下次做。忘了点的话，第二天会问一句。
- **家里的库存**、**想吃清单**（先记个名字和照片，以后再学）。
- **做菜记录**：
  - 打卡时写评分、心得、谁掌勺，拍成品照。
  - 做饭日历按月看，同一天能记好几道；开饭时一起记的菜合成一张「一顿饭」的卡片，能再来一单、分享成图片。
  - 「做过几次」按记录现算。
- **备份与导入**：
  - 整本菜谱（可以带照片）打包成文件，发到微信或者在电脑版微信里存到电脑。不带照片时也能复制成文字。
  - 导回来时同名的菜自动跳过。
  - 附一份中文导入模板，手写的菜谱也能批量导入。
- **几个人同时用**：
  - 先显示手机上的缓存，再同步云上的，没网也能看。
  - 同时改同一道菜时会先问要不要覆盖，不会悄悄盖掉别人的改动。

## 先看看适不适合你

- **要准备的**：一个**个人主体**的小程序账号（免费注册），以及 Windows 或 Mac 上的[微信开发者工具](https://developers.weixin.qq.com/miniprogram/dev/devtools/download.html)。
- **只用体验版**：体验版只有你加的人能打开（个人小程序最多 15 个体验成员），够一家人用。发布上线要过审核，免费云环境上线以后也会到期，原因见[第 9 步](#部署自己的一份)。

## 部署自己的一份

1. **下载代码**：`git clone https://github.com/lazul1te/Xiaoliang_Kitchen.git`，或者在 GitHub 页面上下载 ZIP。
2. **导入项目**：打开微信开发者工具，点「导入」，目录选这个文件夹。AppID 填你自己小程序的，在[小程序后台](https://mp.weixin.qq.com)「开发管理 → 开发设置」里能看到。也可以直接改 `project.config.json` 里的 `appid`。
3. **开通云开发**：点工具栏的「云开发」，按提示开通一个环境（选免费的）。
4. **填环境 ID**：在云开发控制台的「设置」里复制环境 ID，填进 `miniprogram/config.js`。不填的话，会用账号下第一个创建的环境。
5. **部署云函数**：在开发者工具左边的 `cloudfunctions` 里右键 `api` 文件夹，选「上传并部署：云端安装依赖」，等它提示部署成功。
   - 小程序读写数据都走它：它先查你是不是这本小本本的成员，再去读写数据库和照片。
   - 以后改了 `cloudfunctions/api` 里的代码，也要这样重新部署一次。
6. **建数据库集合**：云开发控制台 → 数据库，新建七个集合：`users`、`books`、`categories`、`dishes`、`plans`、`cook_logs`、`meals`。每个集合都打开「数据权限」，选「所有用户不可读写」。
   - 这样只有云函数能读写，别人就算改了小程序的代码，也看不到你们的本本。
   - 忘了建也能用：云函数第一次存东西时会自己建，但建出来的权限不一定对，记得照上面改。
7. **填隐私保护指引**：小程序后台 → 设置 → 服务内容声明 → 用户隐私保护指引，声明三项：
   - 「选中的照片或视频信息」，用途写「给菜品、做菜步骤和做菜记录添加照片」。不填的话选不了照片。
   - 「选中的文件」，用途写「导入菜谱数据文件」。不填的话「从文件导入」选不了聊天里的文件。
   - 「剪切板」，用途写「复制买菜清单；复制、粘贴菜谱数据（导入导出）」。不填的话复制、粘贴都用不了。

   体验版也要声明，没声明的接口会被直接禁用。补上后大约 5 分钟生效，不用提交审核。
8. **编译试试**：在开发者工具里点「编译」。
   - 菜单是空的时候，可以点「放几道示例菜」看效果，以后在「我的」里一键删掉。
   - 到「我的」页最下面点「遇到问题？检查一下云开发」，确认云函数、七个集合都没问题，数据库权限显示 🔒。
9. **发体验版**：
   1. 开发者工具右上角点「上传」。版本号写 `1.0.0` 这样的，备注随便写。
   2. 小程序后台 → 管理 → 版本管理，在「开发版本」里把刚上传的版本「选为体验版」，就能看到体验版二维码。
   3. 小程序后台 → 成员管理 → 体验成员，用微信号把家人加进来。
   4. 大家用微信扫体验版二维码打开。以后在微信下拉的「最近使用」里就能找到。
   5. 以后每次改完代码，重复 1、2 两步，重新打开小程序就是新版本。

   **别点「提交审核」或「发布」**，原因有两个：
   - 发布以后，免费云环境会在上线第 15 天到期，之后要付费。
   - 公开的小程序要过审核，个人主体做「用户自己发内容」的小程序不容易过。
10. **一起记**：家人第一次打开，是 TA 自己的「我的小本本」。你在菜单左上角新建一本家庭本本，进「我的 → 小本本设置」，把家庭码告诉 TA，或者点「邀请家人」发卡片；TA 申请以后，你在同一页点「同意」。

注意：开发者工具和手机上的体验版用的是同一个云环境。在开发者工具里增删的，就是你们的真实数据。

## 从旧版本升级

以前的版本没有小本本，能打开小程序的人共用一份数据。升级以后，这份数据自动变成一本家庭本本「我们家的小本本」，旧数据里加过东西的人自动在里面，不用申请。照着下面的顺序做：

1. **先备份**：在旧版本里「我的 → 备份与导入 → 备份到微信」，勾上带照片，发到自己的微信里存着。
2. **建两个新集合**：云开发控制台 → 数据库，新建 `users` 和 `books`，权限选「所有用户不可读写」。原来那五个集合的权限**先别动**：还没更新的手机要靠它读写。
3. **部署云函数**：右键 `cloudfunctions/api`，选「上传并部署：云端安装依赖」。
4. **打开一次**：在开发者工具里编译、打开小程序。这一步就会把数据变成「我们家的小本本」，会弹窗说一声。看看菜、记录、菜篮是不是都在。
5. **上传体验版**，大家都打开一次新版本。还没更新的手机新加的东西，也会算进「我们家的小本本」。
6. **大家都换成新版本以后**：
   - 数据库里 `categories`、`dishes`、`plans`、`cook_logs`、`meals` 的权限都改成「所有用户不可读写」。「检查一下云开发」里数据库权限显示 🔒 就对了。
   - 云函数列表里旧的 `photo` 可以删掉了。
7. 家人打开后没看到「我们家的小本本」：说明 TA 在旧数据里没加过东西。让 TA 用家庭码申请，你在「我的 → 小本本设置」里同意。

## 一家人一起用

- **看到家人的改动**：一个人改了以后，别人重新打开小程序、隔 15 秒以上再回到页面，或者下拉刷新，就能看到。
- **同时改同一道菜**：后保存的人会被问「要不要覆盖」，不会悄悄把别人的改动盖掉。
- **菜篮和买菜清单是这本里共用的**：一个人点了菜，别人也能看到。买菜时买到一样勾一样，大家同步。
- **其他也共用**：这本的库存、想吃清单、做菜记录都是大家一起的。打卡时可以写「掌勺」是谁。
- **成员**：本主能换家庭码（旧的马上失效）、同意或不同意申请、移出别人。本主退出时，最早加入的人接着当本主；最后一个人退出，这本就删掉了（会先提醒导出备份）。一个人最多加 5 本家庭本本。

## 数据存在哪

- **云数据库**（权限都是「所有用户不可读写」，只有云函数 `api` 能读写）：
  - `users` 每人一条：个人本本是哪本、打开时默认进哪本、上次用的哪本、给 TA 的通知
  - `books` 每本小本本一条：名字、个人还是家庭、本主、成员、加入申请、家庭码
  - `categories` 分类、`dishes` 菜品（原料和步骤都在里面）、`cook_logs` 做菜记录、`meals` 开饭时记下的每一顿：每条都记着是哪本（`bookId`）
  - `plans` 每本各有三条：菜篮（含点菜单）和买菜清单、库存、想吃清单
- **云存储**：按本本放在 `books/<本本id>/` 下面：
  - `covers/` 成品照大图
  - `thumbs/` 小图，列表用，省流量
  - `steps/` 步骤照片
  - `logs/` 打卡照片、整桌照片
  - `wishes/` 想吃清单的照片
  - 旧版本传的照片没有 `books/` 前缀，算「我们家的小本本」的。
- **不单独存的**：「做过几次」「上次做」按做菜记录现算，所以跟记录页永远对得上。
- **手机本地**：每本存一份云上数据的缓存。打开时先显示缓存，没网也能看。

## 备份和导入

- **备份**：「我的 → 备份与导入 → 备份到微信」，把正在用的这本里的菜谱、记录和照片打包成一个文件（几本的话每本各备份一次）。可以：
  - 发到微信聊天里；
  - 在电脑版微信里直接存到电脑；
  - 不带照片时，复制成文字存到备忘录。
- **导回来**：「我的 → 备份与导入 → 从文件导入」，导进正在用的这本。从微信聊天里选文件，或者粘贴复制的内容。同名的菜会跳过，不会重复。
- **一次加好几道新菜**：照着 [`docs/菜谱导入模板.json`](docs/菜谱导入模板.json) 写。小程序的「备份与导入」页里也能复制或发送这份模板。
  - 字段是中文的：菜名、分类、主料（一项写一样，比如「土豆 2个」）、做法（要计时的步骤写「8分钟」）等，模板里有说明。
  - 照片要导入以后，在菜的编辑页里加。

## 安全说明

- **谁能读写数据**：数据库的权限是「所有用户不可读写」，小程序读写都走云函数 `api`。微信会把调用的人是谁直接交给云函数，手机上改不了；云函数先查这个人是不是这本小本本的成员，是才读写。
- **照片**：也由 `api` 以管理员身份换链接、删除，只处理你是成员的那几本里的照片（`books/<本本id>/` 下面）。换出来的链接 10 分钟内有效。
- **加入家庭本本**：家庭码 6 位（没有容易看错的 0、O、1、I、L），一小时内输错 10 次要等一会儿；输对了也只是申请，本主同意才算加入。小程序里看不到别人的微信身份（openid）。
- **还没更新的旧版本**：旧版本直接读写数据库，大家都换成新版本、把数据库权限改成「所有用户不可读写」之前，旧版本看得到所有本本的数据。见[从旧版本升级](#从旧版本升级)第 6 步。

## 常见问题

- **打开就提示「云函数 api 还没部署」**：照部署第 5 步右键 `cloudfunctions/api` 上传部署，部署好以后重新打开小程序。
- **家人看不到我传的照片**：可能是云函数 `api` 没部署，也可能是部署后还没上传新的体验版。可以在「我的」页底部点「检查一下云开发」查一下。
- **点「复制」提示「暂时不能复制」，或者选不了照片、文件**：隐私保护指引里没声明对应的项目（见部署第 7 步）。补上后大约 5 分钟生效。
- **申请了还没通过**：本主在「我的」页会看到小红点，进「小本本设置」点「同意」就行；通过以后，你打开小程序会收到通知。
- **家人改了，我这边还是旧的**：重新打开小程序、隔 15 秒以上再回到页面，或者下拉刷新。看看左上角是不是同一本。
- **开发者工具报找不到模块，或者模拟器卡住**：多半是开发者工具热重载出了问题，退出重开一次。

## 开发

- **代码约定**：各模块怎么配合写在 [`CLAUDE.md`](CLAUDE.md)，它也是给 AI 编程助手看的项目说明。
- **测试**：跑 `npm test`，要 Node.js 20 以上，不用装依赖。
  - 先做静态检查：页面文件、WXML 标签配对、事件处理函数、WXSS 变量。
  - 再用假的 `wx` / `wx.cloud` 把主要流程跑一遍：云函数 `api` 在测试里真的跑（假的云端数据库），模拟三台手机，包括每本分开、申请加入和本主同意、旧数据变成家庭本本。
  - 界面效果还是要在开发者工具里看。
- **图标**：SVG 源文件在 `design/`。改完先 `npm install`（只有第一次要），再 `npm run icons` 导出 PNG。
