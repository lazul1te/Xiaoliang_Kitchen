# 拿手菜小本本

> 好好做饭，也好好记录。

两个人一起记的菜谱微信小程序。用法：
- 像翻餐厅菜单一样挑今天要做的菜，菜篮自动合出买菜清单。
- 做的时候一步一步看，带计时。
- 做完打个卡，日历上记着哪天做了什么。

能打开这个小程序的人（管理员和体验成员）共用一本菜谱，都能看、都能改。它是原生小程序（JavaScript）加微信云开发，不用自己的服务器。用免费环境和体验版就能一直用，不花钱。

## 功能

- **菜单**：左边分类，右边菜品卡片。能按菜名、原料、标签搜；搜不到的一键记进想吃清单。
- **菜谱**：
  - 原料分主料、辅料、调料，带用量。
  - 做法一步一项，每步能配照片、带计时。
  - 还有小贴士、难度、用时、熟练度。
- **烹饪模式**：一步一屏大字显示；计时到点会震动、响提示音；做菜时屏幕不灭。
- **菜篮和买菜清单**：
  - 两个人点的菜都放进菜篮，原料按份数自动合并。
  - 清单会对比家里的库存，家里有的不提醒。
  - 买到一样勾一样，两边同步；也能一键复制发给对方。
- **家里的库存**、**想吃清单**（先记个名字和照片，以后再学）。
- **做菜记录**：
  - 打卡时写评分、心得、谁掌勺，拍成品照。
  - 做饭日历按月看，同一天能记好几道。
  - 「做过几次」按记录现算。
- **备份与导入**：
  - 整本菜谱（可以带照片）打包成文件，发到微信或者在电脑版微信里存到电脑。不带照片时也能复制成文字。
  - 导回来时同名的菜自动跳过。
  - 附一份中文导入模板，手写的菜谱也能批量导入。
- **两个人同时用**：
  - 先显示手机上的缓存，再同步云上的，没网也能看。
  - 同时改同一道菜时会先问要不要覆盖，不会悄悄盖掉对方的改动。

## 先看看适不适合你

- **要准备的**：一个**个人主体**的小程序账号（免费注册），以及 Windows 或 Mac 上的[微信开发者工具](https://developers.weixin.qq.com/miniprogram/dev/devtools/download.html)。
- **只用体验版**：数据是所有能打开小程序的人共用的，而体验版只有你加的人能打开（个人小程序最多 15 个体验成员）。所以它不适合发布上线给陌生人用，原因见[安全说明](#安全说明)。

## 部署自己的一份

1. **下载代码**：`git clone https://github.com/lazul1te/Xiaoliang_Kitchen.git`，或者在 GitHub 页面上下载 ZIP。
2. **导入项目**：打开微信开发者工具，点「导入」，目录选这个文件夹。AppID 填你自己小程序的，在[小程序后台](https://mp.weixin.qq.com)「开发管理 → 开发设置」里能看到。也可以直接改 `project.config.json` 里的 `appid`。
3. **开通云开发**：点工具栏的「云开发」，按提示开通一个环境（选免费的）。
4. **填环境 ID**：在云开发控制台的「设置」里复制环境 ID，填进 `miniprogram/config.js`。不填的话，会用账号下第一个创建的环境。
5. **建数据库集合**：云开发控制台 → 数据库，新建四个集合：`categories`、`dishes`、`plans`、`cook_logs`。每个集合都打开「数据权限」，选「自定义安全规则」，把原来的内容全部换成：
   ```json
   {
     "read": "auth.openid != null",
     "write": "auth.openid != null"
   }
   ```
   这条规则的意思是：能打开这个小程序的人都能读写。另外注意：
   - 不能写 `{ "read": true, "write": true }`，控制台会报 rule invalid。
   - 不要选「仅创建者可读写」：选了看不到对方的菜。
   - 也不要选「所有用户可读，仅创建者可写」：选了改不了对方加的菜。
6. **部署云函数**：在开发者工具左边的 `cloudfunctions` 里右键 `photo` 文件夹，选「上传并部署：云端安装依赖」，等它提示部署成功。
   - 为什么要它：免费环境的云存储只有上传照片的人能读，权限也改不了。对方传的照片，要靠这个云函数换成两个人都能看的链接。
   - 以后改了 `cloudfunctions/photo` 里的代码，也要这样重新部署一次。
7. **填隐私保护指引**：小程序后台 → 设置 → 服务内容声明 → 用户隐私保护指引，声明三项：
   - 「选中的照片或视频信息」，用途写「给菜品、做菜步骤和做菜记录添加照片」。不填的话选不了照片。
   - 「选中的文件」，用途写「导入菜谱数据文件」。不填的话「从文件导入」选不了聊天里的文件。
   - 「剪切板」，用途写「复制买菜清单；复制、粘贴菜谱数据（导入导出）」。不填的话复制、粘贴都用不了。

   体验版也要声明，没声明的接口会被直接禁用。补上后大约 5 分钟生效，不用提交审核。
8. **编译试试**：在开发者工具里点「编译」。
   - 菜单是空的时候，可以点「放几道示例菜」看效果，以后在「我的」里一键删掉。
   - 到「我的」页最下面点「遇到问题？检查一下云开发」，确认四个集合和云函数都没问题。
9. **发体验版**：
   1. 开发者工具右上角点「上传」。版本号写 `1.0.0` 这样的，备注随便写。
   2. 小程序后台 → 管理 → 版本管理，在「开发版本」里把刚上传的版本「选为体验版」，就能看到体验版二维码。
   3. 小程序后台 → 成员管理 → 体验成员，用微信号把对方加进来。
   4. 两个人用微信扫体验版二维码打开。以后在微信下拉的「最近使用」里就能找到。
   5. 以后每次改完代码，重复 1、2 两步，重新打开小程序就是新版本。

   **别点「提交审核」或「发布」**，原因有两个：
   - 现在的数据规则只适合自己人用。
   - 发布以后，免费云环境会在上线第 15 天到期，之后要付费。

注意：开发者工具和手机上的体验版用的是同一个云环境。在开发者工具里增删的，就是你们的真实数据。

## 两个人一起用

- **看到对方的改动**：一方改了以后，另一方重新打开小程序、隔 15 秒以上再回到页面，或者下拉刷新，就能看到。
- **同时改同一道菜**：后保存的人会被问「要不要覆盖」，不会悄悄把对方的改动盖掉。
- **菜篮和买菜清单是共用的**：一个人点了菜，另一个人也能看到。买菜时买到一样勾一样，两边同步。
- **其他也共用**：家里的库存、想吃清单、做菜记录都是两个人一起的。打卡时可以写「掌勺」是谁。

## 数据存在哪

- **云数据库**（两个人共用）：
  - `categories` 分类
  - `dishes` 菜品，原料和步骤都在里面
  - `plans` 几条共用记录：`current` 菜篮和买菜清单、`pantry` 库存、`wishes` 想吃清单
  - `cook_logs` 做菜记录
- **云存储**：
  - `covers/` 成品照大图
  - `thumbs/` 小图，列表用，省流量
  - `steps/` 步骤照片
  - `logs/` 打卡照片
  - `wishes/` 想吃清单的照片
- **不单独存的**：「做过几次」「上次做」按做菜记录现算，所以跟记录页永远对得上。
- **手机本地**：存一份云上数据的缓存。打开时先显示缓存，没网也能看。

## 备份和导入

- **备份**：「我的 → 备份与导入 → 备份到微信」，把菜谱、记录和照片打包成一个文件。可以：
  - 发到微信聊天里；
  - 在电脑版微信里直接存到电脑；
  - 不带照片时，复制成文字存到备忘录。
- **导回来**：「我的 → 备份与导入 → 从文件导入」，从微信聊天里选文件，或者粘贴复制的内容。同名的菜会跳过，不会重复。
- **一次加好几道新菜**：照着 [`docs/菜谱导入模板.json`](docs/菜谱导入模板.json) 写。小程序的「备份与导入」页里也能复制或发送这份模板。
  - 字段是中文的：菜名、分类、主料（一项写一样，比如「土豆 2个」）、做法（要计时的步骤写「8分钟」）等，模板里有说明。
  - 照片要导入以后，在菜的编辑页里加。

## 安全说明

- **谁能读写数据**：数据库规则 `auth.openid != null` 的意思是，**任何能打开这个小程序的微信用户**都能读写全部数据。体验版只有管理员和体验成员能打开。所以只要不发布上线、只加信任的人，数据就只在你们之间。
- **照片云函数**：`photo` 以管理员身份运行，只处理这个环境里 `covers/`、`thumbs/`、`steps/`、`logs/`、`wishes/` 下的文件。它换出来的链接 10 分钟内有效。
- **如果要发布给更多人用**：至少要先把数据按家庭隔开（比如加家庭码或白名单），再相应地改数据库规则和云函数。

## 费用

- 注册个人小程序、用体验版：免费。
- 云开发用的是官方免费环境。写这份说明时（2026 年 10 月），控制台写的活动截止日期是 2026-12-31，之后的规则以官方为准。
- 建议隔一阵就「备份到微信」一次，留一份自己的数据。

## 常见问题

- **对方看不到我传的照片**：可能是 `photo` 云函数没部署，也可能是部署后还没上传新的体验版。可以在「我的」页底部点「检查一下云开发」查一下。
- **点「复制」提示「暂时不能复制」，或者选不了照片、文件**：隐私保护指引里没声明对应的项目（见部署第 7 步）。补上后大约 5 分钟生效。
- **设置数据库权限时报 rule invalid**：规则里不能写 `true`，照部署第 5 步写 `auth.openid != null`。
- **对方改了，我这边还是旧的**：重新打开小程序、隔 15 秒以上再回到页面，或者下拉刷新。
- **开发者工具报找不到模块，或者模拟器卡住**：多半是开发者工具热重载出了问题，退出重开一次。

## 开发

- **代码约定**：各模块怎么配合写在 [`CLAUDE.md`](CLAUDE.md)，它也是给 AI 编程助手看的项目说明。
- **测试**：跑 `npm test`，要 Node.js 20 以上，不用装依赖。
  - 先做静态检查：页面文件、WXML 标签配对、事件处理函数、WXSS 变量。
  - 再用假的 `wx` / `wx.cloud` 把主要流程跑一遍，包括两台手机共用一个数据库、几种权限设错的情况。
  - 界面效果还是要在开发者工具里看。
- **图标**：SVG 源文件在 `design/`。改完先 `npm install`（只有第一次要），再 `npm run icons` 导出 PNG。
